# 가챠 풀 및 학습 스토리 변경

PWA `/api/v1/game/gacha`는 전체 상품 seed와 별개로 고양이 1종과 초기 숲 가구 4종만
하드코딩하고 있었다. 새 상품은 DB에 존재해도 후보에 들어갈 수 없었다.
`ITEM_DEFINITIONS`의 FURNITURE 전체를 사용하는 풀로 바꾸고 프론트도 같은 규칙으로 맞춘다.

- 먹구름 5%, SR 10%(desk/hideout), R 25%(catTree/scratcher), N 60% 유지.
- N은 기존 장식 30%(plant), 기타 가구 30%(sofa/bed/rug/litterBox)로 구성한다.
- 각 묶음의 확률은 해당 묶음 상품에 균등 분배한다. 따라서 기존 개별 상품 확률은 낮아진다.
- 숲·골목·실내·책상·바다 가구와 장식 85종. 벽지·바닥·소모품은 기존 지급 계약 밖이므로 제외.
- 30/300 코인, 1/11회, 중복 고양이 15코인, 멱등성 및 트랜잭션 처리는 그대로다.
- 별도 `/gacha/draws` 정책 주입 API는 변경하지 않는다.

학습 seed는 요청 제목을 `[도와주세요!]`, 실제 요구사항 제목을 `[문제]`로 통일한다.
Python은 연산별 30개 생활 상황, SQL은 7개 생활 상황과 기존 테이블 이름의 의미를 안내한다.
수학적 요구사항, 입력/정답, SQL 테이블·쿼리, 객관식 선택지, 난이도, 보상은 유지한다.
main에서 가져온 비서술 필드 전체의 SHA-256 회귀 검사로 Python 150 / SQL 150 계약을 검증한다.

배포 시 프론트 풀 허용 목록을 먼저 배포하고 백엔드를 배포한다. 백엔드만 먼저 배포하면 이전
프론트가 새 보상 ID를 거부할 수 있다. 배포 후 기존 DB에도 다음 seed를 재실행한다.

가챠 명령은 운영 seed와 코드 배포 사이의 짧은 불일치에도 추첨이 실패하지 않도록, 비용 차감 전에
정적 가구 카탈로그의 누락 행을 결정적 UUID로 `ON CONFLICT DO NOTHING` 보완한다. 이 보완과 비용 차감,
자산 지급은 같은 Unit of Work에 있으므로 실패 시 함께 롤백된다. 전체 이름·가격 갱신과 학습 문구 반영은
아래 seed 절차가 계속 담당한다.

```sh
python -m scripts.seed_game_catalog
python -m scripts.seed_learning_tasks
python -m scripts.seed_sql_tasks
```

학습 seed의 안정된 `[SAMPLE:...]` 키로 기존 행을 갱신하므로 기존 문제 ID와 시도 연결은 유지된다.
이 작업에서 운영 DB seed나 배포를 실행하지 않았으며, 독립 테스트 DB에서 생성/재실행을 검증했다.

Python 채점기는 제출 문서를 각 테스트의 표준 입력과 함께 독립 프로그램으로 실행하고 표준 출력을
비교한다. 특정 함수명이나 `solve()` 래퍼를 요구하지 않으므로 Python seed의 `template_code`는 비워 둔다.
함수 학습 목표가 있는 문제도 함수 활용을 요구할 뿐 채점하지 않는 함수명을 고정하지 않는다. SQL 채점기는
제출한 SQL 문 전체를 실행하므로 모든 코드 과제는 풀이 종류를 노출하지 않는 짧은 안내 주석만 제공한다.

힌트는 Python 연산별로 입력 처리, 조건·자료구조와 다음 풀이 단계를 안내한다. SQL 힌트도 문제별로
`WHERE`, `GROUP BY`, `JOIN`, 서브쿼리, 윈도 함수 등 필요한 절과 적용 순서를 알려 주되 완성 답안은
제공하지 않는다. seed 갱신 시 정답, 테스트 케이스와 객관식 선택지는 그대로 유지한다.
