# 권위 있는 학습·데일리 보상

## 정상 흐름

과제는 `reward_coins`를 공개 조회 계약에 포함한다. 답안 채점이 정답으로 끝나면 서버는
`task_completions(user_id, task_id)` 원장을 먼저 생성하고, 원장이 새로 생성된 경우에만 사용자 잔액과
`task_attempts.coins_awarded`를 같은 트랜잭션에서 증가시킨다. 이미 완료한 과제를 다시 풀면 정답 상태는
반환하지만 지급액은 0이다.

게임 스냅샷은 서버 UTC 날짜를 기준으로 오늘 정답 처리된 서로 다른 과제 UUID, 코드 과제 완료 여부,
개별 데일리 보상 수령 키와 최종 보너스 수령 여부를 반환한다. 클라이언트는
`POST /api/v1/game/daily-rewards/claims`에 `solve-one`, `solve-three`, `finish-code`, `bonus` 중 하나를 보낸다.

## 중복·동시성 방어

- 최초 과제 보상은 사용자·과제 고유 제약과 PostgreSQL `ON CONFLICT DO NOTHING`으로 한 번만 지급한다.
- 데일리 보상은 사용자 행을 잠근 뒤 오늘의 정답 이력을 다시 계산한다.
- `daily_reward_claims(user_id, claim_date, reward_key)` 고유 제약이 재시도와 동시 요청의 중복 지급을 막는다.
- 최종 보너스는 같은 날짜의 세 개 개별 보상 원장이 모두 존재할 때만 지급한다.
- 마이그레이션 이전 정답 이력은 지급액 0의 완료 원장으로 이관해 기존 사용자에게 소급 중복 보상하지 않는다.

## 오류 계약

- 이미 수령함: HTTP 409, `already-claimed`
- 서버 진행도 미달: HTTP 409, `reward-not-ready`
- 지원하지 않는 보상 키: 요청 스키마에서 HTTP 422

## 학습 초기화와 고양이 기억 삭제

`POST /api/v1/game/learning/reset`은 사용자의 `learning_reset_at`을 현재 UTC 시각으로 옮기고 숙련도 집계를
비운다. 추천 완료 상태, 약점 분석과 오늘의 과제 진행도는 이 경계 이후 답안만 사용한다. 기존 답안과
`task_completions` 보상 원장은 감사 및 중복 보상 방지를 위해 삭제하지 않으며, 잔액·출석·데일리 수령
원장도 유지한다. 초기화 직전에 제출되어 경계 뒤에 채점된 답안은 새 진도나 보상에 포함하지 않는다.

고양이 기억은 게임 스냅샷의 각 고양이에 시간순으로 포함된다. `DELETE /api/v1/game/cat-memories`는 인증
사용자가 보유한 고양이 자산을 하위 질의로 제한해 다른 사용자의 기억을 삭제할 수 없게 한다.

## 검증

`pytest`는 모델 등록, PostgreSQL 마이그레이션, 기존 데이터 트리거와 보상 명령 단위 테스트를 포함한다.
통합 환경에서는 최초 정답의 설정 보상 지급, 같은 과제 재정답의 0 지급, 데일리 보상 1회 지급과 재요청
409를 함께 확인한다.
